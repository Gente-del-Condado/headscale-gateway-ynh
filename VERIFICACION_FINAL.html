    Validación y límites conocidos

    Revisión de dependencias de la versión 1.4.6

    Revisión del 11 de noviembre de 2026. Se actualizan Caddy a 2.11.5, go-jose a 4.1.6, QUIC a 0.63.0 y las dependencias de red y compresión. La compilación requiere Go 1.27.4 para incorporar las correcciones de la biblioteca estándar.

    La bandeja fija glob 14.0.4 y minimatch 11.0.8 mediante overrides. El empaquetador ASAR todavía solicita versiones principales anteriores. Las pruebas comprobaron la creación y lectura de un ASAR, el empaquetado Linux completo y el arranque Electron con autenticación de prueba, aislamiento del renderer y almacenamiento cifrado. npm audit y govulncheck registraron cero vulnerabilidades, incluidos los avisos de módulos sin llamadas detectadas.

    El aviso GHSA-wwhq-w58m-w29c carece de versión corregida declarada en GitHub, pero Caddy 2.11.5 ya elimina la segunda expansión de los valores en VarsMatcher y MatchVarsRE. Los módulos HTTP de Caddy afectados por ese aviso no forman parte de los paquetes compilados del Gateway.

    Para repetir el análisis desde src/, ejecuta go run golang.org/x/vuln/cmd/govulncheck@v1.9.0 -show verbose ./.... Desde src/desktop/, ejecuta npm ci, npm audit, npm test y npm run pack. La prueba npm run smoke requiere un escritorio gráfico.

    Se han retirado metadatos del escritorio y una semilla de traducción que ya había sido sustituida por los catálogos. Se conservan los binarios y el archivo de fuentes requeridos por los instaladores privados, las licencias y la APK actual de pruebas. La salida HTML se genera en builds/manual/.

    Validaciones previas y pendientes

    La revisión de estructura del 5 de noviembre registró compilaciones Linux, Windows y macOS, despliegue aislado, recuperación en consola y comprobaciones de firma y alineación de la APK Android. Esas comprobaciones no se vuelven a atribuir automáticamente a cada edición de documentación.

    Las pruebas funcionales previas con Headscale HTTPS, servicios, PKI, copias, restauración y túnel Android se describen en ANDROID.md. Android Lint registró 0 errores y 23 avisos; la instrumentación de la APK reorganizada se compiló, pero no se volvió a ejecutar en aquella revisión.

    Siguen pendientes la aceptación completa en Home Assistant OS y en una VM YunoHost, package_check, teléfonos físicos, cambios reales de red y batería, y proveedores DNS/ACME reales. Las pruebas aisladas y los simuladores no sustituyen estas comprobaciones.

    El workflow de GitHub Pages está preparado y el HTML se ha probado localmente. La publicación real requiere habilitar Pages en el repositorio elegido. Esta actualización no constituye un despliegue web ni una nueva publicación de APK.

    Repetir la comprobación

    Desde la raíz del proyecto:

    bash tools/verify.sh
builds/docs-env/bin/python -m mkdocs build --strict
python3 tools/check_manual.py builds/manual
sha256sum --check --quiet CONTENIDO.sha256

    Prepara el entorno documental según MANUAL_WEB.md. La suma corresponde al contenido entregado; cambiar un archivo hace necesario actualizarla. Consulta CONTRIBUTING.md antes de preparar un commit.

    Comprobar una exportación

    El archivo externo .zip.sha256 verifica el ZIP. Dentro, CONTENIDO.sha256 contiene la suma de cada archivo entregado. Compruébalo desde la carpeta extraída antes de modificarla. El exportador incluye fuentes nativas, manuales, capturas, herramientas del manual y paquetes instalables. Excluye historial Git, cachés, credenciales, SQLite y perfiles de ejecución.

    La guía de Git y entregas explica cómo generar una exportación y revisarla. Los paquetes de ejecutables incluyen también los recursos de las guías, como las capturas, conservando sus subdirectorios.
